## 브라우저 실사용 QA (Sonnet 담당 영역 — UI/UX 실동작 검증)

Node 하네스는 DOM을 스텁으로 흘려보내 로직만 검증했을 뿐, 실제 클릭·렌더링은 이번에 처음 확인했다.
클로드인크롬으로 배포 사이트를 직접 조작하며 Phase 1→2→3→4 전 구간을 실제로 눌러보고, 그 과정에서 실사용 버그 2건을 새로 발견·수정했다.

1. **함수별 주석 발췌가 이전 함수의 주석까지 끌어옴** — `attachComments()`가 `f.startLine-6` 고정 lookback만 쓰고 이전 함수의 `endLine`을 고려하지 않아서, 함수 간격이 6줄보다 좁으면 이전 함수 끝의 주석이 다음 함수 설명에 섞였다.
   실측: 샘플 코드에서 `CheckGearStatus()` 상세 패널에 `CheckSeatBeltStatus()`의 "벨트 미착용 시 출력 제한" 주석이 함께 표시됨을 화면에서 확인.
   수정: 정렬된 함수 목록에서 `직전 함수.endLine + 1` 을 하한선으로 추가 — 함수 경계를 넘지 않도록 clamp.
2. **짧은 키워드(3자 이하)가 다른 단어 안에 우연히 포함되는 오탐** — `classify()`/`describeFunc()`가 `문자열.includes(키워드)` 부분일치를 썼는데, `'ain'`(센서/신호 카테고리, `Make_AIN` 대응용)이 `'maintenance'`(유지보수) 안에 그대로 포함되어 있어 `Check_Maintenance_Info()`가 "maintenance/ain 관련" 으로 이중 태깅되는 등 카테고리 오분류가 발생했다.
   수정: 3자 이하 키워드는 토큰 완전일치·텍스트는 단어 경계(`\b`) 매칭으로 전환(`kwHitTok`/`kwHitText` 헬퍼로 통일). 카테고리 2(차량 편의 및 보안)에 `hill`/`assist` 키워드 추가(`HillStartAssistControl_Control` 계열 인식 개선).
   실측 영향: 실제 Alogrithm.c 카테고리 분포가 수정 전/후로 유의미하게 바뀜 — 유지보수 3→5, 안전/Fail-Safe 8→10, 사양서 수록 함수 27→29. 오탐이 실제로 결과를 왜곡하고 있었다는 뜻이므로 수정 전 배포판을 그대로 뒀으면 안 됐다.

두 수정 모두 재적용 후 `node --check` 구문 검증 + 실제 `Alogrithm.c` 전체 파이프라인 재실행 + `docx` 생성 후 LibreOffice 변환까지 재확인(CRC 손상 없음, 정상 변환)했고, 브라우저에서 Phase 1(샘플 로드)→2(분석·상세·SVG 흐름도)→3(사양서 미리보기)→4(교차검증·다운로드) 전 구간 클릭 동작을 재확인했다.
